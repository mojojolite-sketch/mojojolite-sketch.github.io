Pearl Research Labs：协议、算力与经济学

2026-10-28 研究工作稿。经营名称由 Together AI 合作公告确认；法律实体未核验。用户转交的 session-2026-10-28-pearl-handoff.md 是对话交接，不是证据。登记版本：pearl-research-labs@1、pearl-int-whitepaper@1、pearl-pip3@1。以下为本轮研究整理，未经独立 reviewer 复核。

产品与协议

Pearl 有推理 API 与 PoW 链；API 文档称预充值美元、按输入/缓存/输出 token 计费。未发现已开放的 GPU 小时撮合市场或外部 GPU 所有者接入调度的完整证据。收入、客户数量、实际付费推理量尚未披露。

INT 白皮书提出两用计算：用链状态和输入承诺生成低秩噪声 E、F；计算 (A+E)(B+F)；由结果减去 EB+AF+EF 得 AB；对计算过程分块累计摘要，满足难度条件后提交 Plonky2 零知识证明。低秩校正本身带来捷径风险，因此要求计算轨迹。此证明针对规定计算及其一致性，不证明矩阵来自付费请求。

官方 miner README：vLLM plugin、NoisyGEMM/CUDA、miner-base、gateway、全节点；文档当前测试范围 sm90 H100/H200。不能把该限制推广到社区纯挖矿程序。

FP8 PIP-3 当前页面为 Draft，需硬分叉；与 INT 不兼容，输出不再 bit-exact，依赖架构与实现。已检索来源未证实生效高度；GPU 支持范围可能变化。新 FP8 规格 和用户给的 INT 白皮书不是同一版本。

有用性与客户

Together 2026-05-15 宣布 Gemma endpoint 折扣超过 25%，称折扣由未来加密资产发行价值抵消；公告未说明比较基准，不能直接写作较通常定价；为合作方说法，不是已审计贡献利润，也非独立终端客户满意度。

Together 同时推理与挖矿：代码路径及生产证据边界

Together 2026-05-15 公告称其合作 endpoint 在推理时同时产生 PRL；Pearl 模型卡说明该 checkpoint 旨在与 vLLM mining plugin、pearld 节点和 pearl-gateway 配合。官方 miner README给出 NoisyGEMM 替换量化线性算子、从矩阵计算提取 PoW、gateway 与全节点交互的路径。它证明公开实现和部署方案，不证明 Together 实际使用相同提交、节点、显卡配置，也未看到其生产日志、被接受区块或服务统计。模型卡列的两套模型质量测试不是开关挖矿的吞吐/延迟对照。

在 2026-10-28 读取的 master config.yaml 中，门槛为 m≥1024、n≥256、k≥1024；config.py 明确任一维等于 1 时返回 false，未达到阈值则不走 noisy GEMM。维度与批次、序列长度和算子有关；不等于所有 decode 都无挖矿，也不能推广到不同提交或 Together 私有部署。GitHub commit SHA 此轮未取得。

Issue #83 发帖人 2026-05-05 称，在 8×H200、其配置与 26,000 多个请求下未触发 PoUW；贡献者回复称较大的 prefill 工作量更易达到门槛。这是用户自报与维护者讨论，不是对 Together 的测试，不应把推理服务 batch 与加密矿池混为一谈。

Pearl 技术文章称，在指定条件下，Llama 70B、4×H200 DP=4 的端到端开销 +5.08%；DeepSeek V3.2、8×H200 DP=8+EP 为 +3.9%。这是厂商所报的不同模型与配置，不是 Together Gemma 的实测，也没有在本轮独立复现；不支持公告的每个 GPU cycle 都无额外成本。

PRL 到哪里、谁分配和变现？

官方节点 README要求配置矿工的 Taproot 地址，节点及 gateway 使用 mining address；测试代码展示区块模板以 mining_address 构造。这表明普通自营路径可以指定奖励目标地址，不揭示 Together 的实际地址或控制权。一个有效区块的奖励归指定接收输出；矿池、托管方、合同分成与后续转账各有额外规则。

Castle Labs 研究称 Together 自行运行挖矿基础设施并用 PRL 奖励补贴客户，这是第三方归属说法，其底层合同、钱包和卖币证据本轮未找到，不能据此确定法定所有权或实际兑现。Together 公告称以未来发行价值抵消折扣，尚未提供钱包、币量、收入分配比例、收款人、转账、销售记录或合同。将 PRL 按市价估值是潜在收入；卖币或其他结算形成可使用资金才是实际变现，不能把发行值自动视作已实现美元。

网络安全：GPU 准入、攻击成本与共识实现

5.08% / 3.9% 是厂商在特定模型、GPU 配置下报告的推理增加开销，不是全网安全预算、攻击者的 GPU 租金或 51% 攻击成本。BTC 的 SHA-256 主要由 ASIC 挖矿，普通 GPU 可计算 SHA-256 但难有经济竞争力；Pearl 现行 INT PoW 可用多代通用 GPU 及部分其他硬件。单机门槛低有利于参与，也让现有或可租算力更易被短期调动，是否能攻击取决于同一时段能控制的有效网络算力、价格、租赁可得性、矿池和诚实算力反应，不能只凭单卡性能判断。

Pearl 通过难度目标使矿工竞争区块，节点验证交易规则和有效 PoW 证明，采用累计工作量的分支选择；攻击者拥有多数有效算力可以提高重组、双花或审查风险，但无法使遵守规则的节点接受无效签名或凭空增发。少于 50% 也可能概率性重组浅确认，时间、确认深度和攻击者持有/新增算力口径需分别写明。Bitcoin 节点验证、Pearl INT 白皮书。

2026-10-28 Pearlchain.live 快照：Kryptex 244 个区块、24h coinbase 归属出块占比 50.3%，PearlHash 18.6%、PearlFortune 9.7%，4.3% 未归属；数据为第三方标签与短样本，24小时出块占比不是持续有效算力精确份额，不等于一个人持有全部硬件，也不证明攻击或串谋。池控制模板的实际范围、矿工能多快转池未核实。另一 PearlSonar 页面同日快照 Kryptex 报 49.39% 网络份额、24h 248 个块、总块数 487，指标和时点不同；不要把两个数字混作同一时刻。池运营者若集中模板决策会带来可执行权风险。

已发生共识规则修订的直接证据：Pearl PR #275 于 2026-08-05 合并，写明原有 jackpot 边界让更高噪声 rank 可能以同等工作得到更容易的门槛，修订采用最低 rank 128 和 128/rank 惩罚，mainnet 配置高度 96251；这是规则缺陷与修订证据，不单独证明实际恶意攻击、盗币或双花。另 PR #280引入 salted noise seed 和 V3 certificate；不能由 PR 合并本身推断链上攻击发生。

经济学反方：Rafael Pass 预印本在自由进入、竞争均衡等模型条件下推导多数攻击成本与区块奖励预算相联系；作者披露研究时为 Pearl 咨询。其指标是约定的单期机会成本并对攻击期间奖励可变现比例作假设，不是现实网络实测或无条件安全保证；租赁供给、算力集中、价格冲击、串通及模型漏洞仍需验证。可把短时租用攻击的粗框架写为“算力租金 + 能耗/服务等增量成本 + 执行成本 − 可实现收益”，但没有可锁定的海量同配置现货价格、时长和供给曲线，不估计具体攻击价。

安全与有用性是两道题：随机矩阵也可能构成有效计算，不证明有效工作来自真实客户；但随机工作仍可能消耗算力并提供 PoW 安全。反过来，零知识证明确认协议规定的计算，不能保证实际经济价值、代码没有漏洞或网络不被多数算力攻击。Bitcoin 与 Pearl 虽都常用 EH/s 标注，分别是 SHA-256 和 Pearl 专属工作估算，不能直接相除或用作安全倍数。

发行、算力和收益

总供应上限 21 亿，194 秒目标出块，发行平滑衰减，H=650226 区块时累计约 50%，非比特币阶梯式减半。矿工期望收益约为有效算力占比×单位时间发行加手续费×币价×(1-矿池费)，之后减电费、维护、折旧和交易摩擦。不是 PRL 与 GPU 小时的固定兑换。

Minerstat 的一次网页读取显示 81.63 EH/s、难度 49.30M、区块奖励 2.22k PRL；其页面币价 $0.10 与同页历史区间 $1.04–2.34 以及其他服务报价不一致，身份/数据冲突，不能直接采用。另一 MiningBoard 摘录 90.18 EH/s 与 $1.75；快照非同步。5 月论文 24 EH/s，2026-10-23 浏览器 73.87 EH/s；不同来源与窗口仅可表明数量级变化，不构成同源历史曲线或 GPU 台数。

情景计算：81.63 EH/s、2220 PRL/块、194 秒、$1.75/PRL（假设，非核实成交价）、1% pool fee；24 小时运行，不含交易费。年化或未来盈利不能由该静态截面推断。GPU功耗仅卡功率，$0.15/kWh；整机和制冷另算。RTX 4090 330 TH/s、370 W，RTX 5090 400 TH/s、520 W，RTX 5080 210 TH/s、220 W，5070 Ti 175 TH/s、200 W，取 WhatToMine 输入；H100 743 TH/s、698W 取 Linkrra，不同测试工具故不可精确横比。出租方案的成交率、净分成和墙上功耗必须实测；Vast FAQ称 host 得成功任务收入 75%，报价与 host 设定价格存在差异，不可直接以客户最低报价作为 host payout。

分布式算力竞对：业务先于估值
