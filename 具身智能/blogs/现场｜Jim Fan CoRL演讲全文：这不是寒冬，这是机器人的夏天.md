# 现场｜Jim Fan CoRL演讲全文：这不是寒冬，这是机器人的夏天

> [!IMPORTANT]
> 用户关注点（TG）：有趣有趣，Jim fan的露面频率越来越高了：下来，GR00T 2 不只是一个模型检查点。我们正在模糊 System 1 和 System 2 的边界，我们把这称为“统一认知”。看一个指令的例子：按可回收物、厨余垃圾，以及其他复杂标准，对垃圾进行分类。Astra 理解场景中的语义，并直接在画面上绘制引导信息。我们把这个新接口称为 WAM API。GR00T 原生支持这种视觉引导。这样一来，我们就能把推理部分分离出来。

## 针对性追查与回应

> 场景与利益相关性（信源归属）：本文为 NVIDIA GEAR Lab 负责人 Jim Fan（范麟熙） 在 CoRL（机器人学习会议） 上的主题演讲实录（由公众号「具身纪元」Marilyn Liu 现场编译，内嵌 NVIDIA 官方技术白皮书图 6、图 9 与项目页静态图）。作为英伟达机器人全栈生态的官方发布演讲，其核心商业激励是通过开源模型权重（GR00T 2）、数据引擎（Flora）、数据集（Human-1M）与仿真器（SimFoundry），将全球具身开发者绑定至英伟达机载推理芯片（Jetson Thor + Jetson Orin）与云端训练算力底座。阅读时需区分「经白皮书验证的系统架构」与「舞台精选高光 Demo 的泛化边界」。

### 一、回应你的核心关注点：为什么「WAM API（视觉画图引导）」是连接 System 2（Astra）与 System 1（GR00T 2）关键的工程解耦？

你敏锐抓到的这段话——*“Astra 理解场景中的语义，并直接在画面上绘制引导信息（WAM API），GR00T 原生支持这种视觉引导，从而把推理部分分离出来”*——其实是整场演讲在架构设计上最值得深挖的拐点：

#### 1. 过去具身 VLA（Vision-Language-Action）的死结：参数量与控制频率的物理悖论
* 如果把 System 2 和 System 1 塞进同一个超大模型（端到端巨型 VLA）：要理解“按可回收物、厨余垃圾及其他复杂标准分类”或求解“汉诺塔递归算法”，模型需要百亿/千亿级参数的常识与多步逻辑推理能力（如前沿多模态推理模型 Astra 或 jev）；但机载芯片（如 Jetson Thor）要求毫秒级实时闭环反应，跑不动百亿级大模型的高频控制。
* 如果只用小模型（如 20 亿参数的 GR00T 2）硬扛一切：正如 Jim Fan 在演讲中坦言——“让一个 20 亿参数的模型自己去编写汉诺塔递归代码，完全没有必要。” 小模型擅长高频肌肉记忆与接触物理，但语义泛化与长程状态跟踪极易迷失。

#### 2. NVIDIA 的「统一认知（Unified Cognition）」三层接口拆解：用像素空间和状态空间取代纯文本胶水
过去双系统架构（System 2 + System 1）失败的主要原因，是两者之间只用纯文本子指令（如 "pick up the green bottle"）通信——文本丢失了精确的 3D 空间坐标、抓取朝向与接触点几何信息。Jim Fan 这次给出了 三种带宽逐级递增的跨系统接口：

| 协同接口名称 | 信息传递介质 | System 2（Astra）做什么？ | System 1（GR00T 2，20亿参数）做什么？ | 典型验证任务与解决的死穴 |
| :--- | :--- | :--- | :--- | :--- |
| ① WAM API<br>*(视觉目标绘制引导)* | 相机画面像素层直接叠加视觉标记（Visual Overlay / Goal Sketch） | 理解复杂规则（垃圾分类标准、汉诺塔递归步骤），直接在当前 RGB 画面上画出箭头/目标框/轨迹引导 | 原生将「带视觉涂鸦引导的图像」作为条件输入，预测未来画面与关节动作，无需理解背后的高层逻辑 | 复杂标准垃圾分类、零样本物理汉诺塔递归（彻底免除 20B 小模型的逻辑推理负担，且避开了纯文本指令指代不清的问题） |
| ② WAM Edit<br>*(本体感知监控与增量动作修正)* | 视频流 + 本体感知状态（Proprioception）→ 动作增量干预 | 实时盯住画面与机械臂本体状态，在周期性重复动作或精细调节中充当“计数器与校准器”，仅在必要时下发增量修正 | 独立承担 95%+ 的高频连续动作生成，在收到 Astra 的停止/微调信号时平滑切换 | 化学实验两步蘸取计数 + 显微镜旋钮对焦（解决纯扩散策略在重复动作中“数不清自己做了第几次、陷入死循环”的进度丢失顽疾） |
| ③ ASPIRE<br>*(代码即策略守护框架)* | 原生扩散策略 $\leftrightarrow$ Code-as-Policy 恢复例程切换 | 先在仿真环境（SimFoundry）中免梯度下降（Gradient-free）探索编写代码技能库；真机出错时作为“守护天使”触发恢复例程 | 执行高灵巧度接触动作；一旦装错零件（如上方机翼装反），交由 ASPIRE 拆解复位后重新接管 | 整夜无间断飞机模型混料装配（解决长时程任务超过 3–5 分钟、20+ 步骤后局部误差累积导致任务崩溃的痛点） |

* ✅ 架构洞察（本工作台推断）：为什么 WAM API 选择“在画面上直接画图引导”而不是传 3D 坐标？因为 GR00T 2 本质是一个在像素空间“做梦”（联合预测未来视频帧与动作）的世界—动作模型（WAM）。既然它的输入和预测目标都在 2D 多视角图像空间，让 Astra 直接在图像像素上画引导线，与 GR00T 2 的视觉 Token 空间是 100% 同构对齐的，连相机外参标定误差都一并绕开了。

### 二、全文硬核工程细节与参数全量拆解（去水保干）

#### Layer 1：模型与机载计算架构（GR00T 2 × GR00T 2 Turbo × SONIC 三级控制）
1. GR00T 2 基础架构：
   * 参数规模与模态：20 亿（2B）参数的世界—动作模型（World-Action Model, WAM），接收 语言指令 + 多视角相机画面 + 机器人本体状态 作为输入。
   * 联合扩散解码：不同于只输出动作向量的传统 VLA，GR00T 2 在单次扩散过程（Single Diffusion Pass）中联合解码未来几帧像素画面（视频预测“做梦”）与动作序列，把“世界将如何变化”与“机器人应如何行动”绑定在同一表征空间。
2. GR00T 2 Turbo 推理加速：
   * 通过将空间视频 Token 数量压缩至原来的四分之一（1/4），在保持动作精度前提下大幅降低计算延迟；与基线技术相比，GR00T 2 和 Turbo 相较过往 SOTA 方法取得两位数百分比的性能提升。
3. 真机双芯片三级控制拓扑（白皮书图 9 核心参数）：
   * 上层芯片（Jetson Thor）：运行 GR00T 2 Turbo，每次推理块处理 80 个动作 token；
   * 下层芯片（Jetson Orin）：运行全身控制器 SONIC，以 50 Hz 频率执行高频全身平衡与下肢/躯干控制；
   * 真机合作硬件生态：演讲 Demo 集合了 Sharpa（灵巧手）、星动纪元（灵巧手/人形）与 天机（机械臂）。

#### Layer 2：跨域适配（Cross-Adapt / 论文命名 X-Adapt）与四条数据 Pipeline
核心目标：在容易低成本采集数据的源域收集演示，通过微调 GR00T 2 检查点，实现向目标真机新任务的迁移。
* ⚠️ “零样本（Zero-Shot）”口径核查（本工作台核查）：文中导读与论文明确界定——这里的“零样本”是指针对目标机器人上的该项新任务未采过真机遥操作数据；但对于人体动捕和 UMI 路径，底层仍需使用目标机器人在其他任务上的已有数据来锚定跨本体的视觉与运动学对应关系（并非对目标机器人本体完全零先验）。
* 四条异构数据采集与转换管线对比：

| 采集源域 | 代表设备 / 管线 | 跨本体转换机制 | 演讲实测验证任务 |
| :--- | :--- | :--- | :--- |
| ① 手持无源夹爪 | UMI 夹爪 → YAM 夹爪 | 处理视角、运动学与动作空间映射；仅用人类手持 UMI 数据微调 GR00T 2，迁移至外观截然不同的 YAM 机器人夹爪 | 长时程工业零件装配任务 |
| ② 人类动捕手套 | Mocap 手套 → 机器人手/臂 | 捕捉人类手部高频轨迹，支持采集遥操作极难完成的高动态动作 | 粗盐过滤（放滤纸、润湿、倒盐水）及仓库产线动态抛掷（Throwing） |
| ③ 1:1 机械外骨骼 | DexUMI 外骨骼 → 机器人灵巧手 | 外骨骼与目标机械手具备 1:1 机械关节映射（同构手型可直接用关节角，异构手型需重映射）；靠 GR00T 2 视频联合训练跨越外骨骼与真机手的外观视觉差异 | 自主持刀切香蕉、精细手腕/手指扭转动作 |
| ④ 仿真闭环管线 | SimFoundry Real-to-Sim-to-Real | 完整 6 步管线：人类视频 → 场景与运动重建 → 仿真强化学习 (RL) → 带域随机化扰动的合成数据生成 → 微调 GR00T 2 → 真机零样本部署 | 搭配 SONIC 完成全身移动操作（实验室收拾脏毛巾、咖啡馆值班清洁、派对卖爆米花） |

#### Layer 3：长时程精细操作实测（3–5 分钟、20+ 步骤、1 倍速无剪辑段）
Jim Fan 强调长时程移动操作（loco-manipulation）一旦超过 3–5 分钟、20 多个步骤，单步局部误差会向后指数级累积：
1. 数据中心服务器内存条（RAM）拔插更换：全自主、1 倍速、无剪辑完成精密卡槽对准与按压（调侃为“物理世界递归自我改进 RSI 第一步”）；
2. UPS 门店包裹贴标与扫码：仅用 1 小时示范数据 训练，完成「握持剪刀裁切标签 → 双手配合剥下背纸（保留 1 倍速实时画面）→ 粘贴至包裹 → 扫码」全流程；
3. 高中化学粗盐过滤实验 + 自主清理重置：舀盐入烧杯溶解 → 转移至过滤架 → 倾倒过滤 → 做完实验后机器人自主清理台面（减少研究人员手动重置场景时间）。

#### Layer 4：六大开源技术栈全家桶（2026 年 12 月 – 2027 年初）
演讲宣布将开放从硬件图纸到数据标注、仿真、模型的完整工具链：
1. 模型与算法（12 月开源）：GR00T 2 权重、GR00T 2 Turbo 权重、Cross-Adapt (X-Adapt) 跨域适配代码；
2. 物理验证仿真引擎（SimFoundry）：支持粒子物理、关节化物体的 Real-to-Sim 管线，可由 Astra 辅助自动构建环境；SimFoundry 1.0 即日可用，2.0 将于 2027 年初推出；
3. 智能体执行框架（ASPIRE）：开源支持免梯度下降持续积累技能库与错误恢复的运行时框架；
4. 大规模数据整理与标注套件（Flora）：包含时序切分（Flora-TempSeg）、描述标注（Flora-Captioner）、自动评估与奖励模型（Flora-Rewarder）；本地部署 Flora 在同等标注性能下，成本降至调用 Astra 的约 1/125（0.8%）；
5. 人类训练数据集（Human-1M）：内部百万小时级高质量训练数据计划，即日首批开源 10 万小时（100K hours）；
6. 开源数采硬件图纸：完全公开 UMI、DexUMI 外骨骼等设备的 CAD 图纸与 BOM，支持开发者在车库自制。

### 三、观点与可反驳条件

* 观点：
  1. 「视频联合预测（WAM）+ 像素级视觉引导（WAM API）」正在成为具身 System 1 与 System 2 解耦的标准范式：相比强行训练百亿参数单体 VLA，用 20 亿参数的 GR00T 2 Turbo（空间视频 Token 砍至 1/4）负责 Jetson Thor 本地高频反应，再由上层大模型通过画面涂鸦（WAM API）、状态计数干预（WAM Edit）和代码恢复例程（ASPIRE）做稀疏接管，在工程落地性、机载算力成本和长程错误恢复上明显优于纯端到端黑盒大模型。
  2. NVIDIA 开源全栈（GR00T 2 + SimFoundry + Flora + Human-1M + DexUMI）的真实商业锚点是锁死「数据标注本地化算力 + Jetson Thor/Orin 机载双芯架构」生态标准。
* 推翻条件：
  1. 推翻条件 1（WAM 视频联合预测的推理算力性价比证伪）：GR00T 2 在扩散过程中联合解码未来视频帧与动作，虽有助于跨本体视觉对齐（X-Adapt），但消耗了大量算力在像素生成上。若 2026 年 12 月开源权重后，第三方实测表明：不预测像素、仅在隐空间（Latent Space，如 JEPA 或纯 Action Expert）对齐的同规模模型 在 X-Adapt 跨本体迁移成功率上与 GR00T 2 持平，且推理延迟再降 50% 以上，则“像素级做梦（Pixel-space Video Prediction）”并非必要路径。
  2. 推翻条件 2（WAM API 2D 视觉涂鸦在重度遮挡/纯触觉盲操场景失效）：若在腔体内部装配、柔性线束盲插等相机视线被机械手自身严重遮挡的场景中，上层 Astra 无法在 2D 画面上画出有效引导（WAM API 失效），且 ASPIRE 代码恢复例程在非结构化家庭杂乱环境中的死锁率超过 20%，则这套双系统解耦架构仍局限于视线无遮挡的桌面/半结构化任务。
