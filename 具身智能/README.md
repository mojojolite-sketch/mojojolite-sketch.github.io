# 具身智能

以机器人完成真实物理任务为中心，按 System 0（运控平衡）— System 1（操作执行：VLA/WAM 与数据基建）— System 2（全局规划与 Code-as-Policy 编排）三层演化追踪技术收敛、B300 千万小时算力账本与商业落地护城河。

## 当前研究重点与核心判断

- ==核心矛盾==：行业要求「够聪明 + 够快」的可复用物理动作在换任务、换环境、换本体后通过真实工位 UPH、良率、错误恢复与 ROI 验收；真实频率墙由物理规律锁死为伺服 PD 1,000 Hz（1 ms）→ S0 小脑 50–100 Hz（10–20 ms）→ 端侧 VLA/WAM 5–15 Hz（70–125 ms，靠 Action Chunking 填满）→ 云端 S2 0.1–4 Hz（通用多模态 LLM 0.2–2 Hz，专有动作块网关如 Gemini Robotics ~250 ms / $\pi_{0.7}$ RTC 240–300 ms 约 3–4 Hz）。
- ==三层演化与 S1 双向夹击==：纠正将 SONIC 与 $\pi$ 混谈的旧判断——S0 全身运控小脑已过蒸馏底座门槛并正向吸收轻量视觉适应地形（[SONIC](blogs/%E4%B8%93%E8%AE%BF%E7%BD%97%E6%AD%A3%E5%AE%9C%EF%BC%9A%E5%85%B3%E4%BA%8ESONIC%E5%85%A8%E8%BA%AB%E6%8E%A7%E5%88%B6%E6%A1%86%E6%9E%B6%E7%9A%84%E8%AE%BF%E8%B0%88.md)、[SuperMimic](blogs/SuperMimic%EF%BC%88BAIR%20_%20CoRL%202026%20%E6%9C%80%E4%BD%B3%E8%AE%BA%E6%96%87%EF%BC%89%EF%BC%9A%E5%8D%95%E4%B8%AA%E5%8F%AF%E5%BE%AE%E4%B8%96%E7%95%8C%E6%A8%A1%E5%9E%8B%E5%B0%86%E4%BA%BA%E5%BD%A2%E5%85%A8%E8%BA%AB%E6%8E%A7%E5%88%B6%E7%AE%97%E5%8A%9B%E9%99%8D%E4%BD%8E%E8%B6%85%201%2C000%20%E5%80%8D.md)、TeleAI×伽马 NEXUS）；真正卡在速度与数据中间的是 S1（[GR00T 2 Turbo](blogs/GR00T%202%20Official%20Technical%20Release_%20Scaling%20World-Action%20Models%20on%20402%2C000%20Hours%20of%20Human%20Video%20with%20X-Adapt%20%26.md) Thor 124 ms、Motubrain 11 Hz、[Pi API Beta & π0.7](blogs/Physical%20Intelligence%20Releases%20Pi%20API%20Beta%20%26%20%CF%800.7%20with%20Multi-Scale%20Embodied%20Memory%20%28MEM%29%20for%2010%2B%20Min%20Long-Hori.md)）。架构分叉在「路径 α（S2 云端 LLM 提速 10× 向下吞并）」与「路径 β（S1 端侧保持尺寸且泛化升维）」之间摇摆，但广域网抖动、无物理接地（[Goodfire VLA 神经几何解剖](blogs/%E3%80%90%E6%85%A2%E7%A7%91%E7%A0%94%E3%80%91VLA%E5%A6%82%E4%BD%95%E5%9C%A8%E5%86%85%E9%83%A8%E8%A1%A8%E7%A4%BA%E7%89%A9%E7%90%86%E4%B8%96%E7%95%8C%EF%BC%9F.md)）及 1–10 ms 刚性接触力闭环，使终局更倾向「端侧融合」（[NVIDIA VFlash](blogs/%E8%8B%B1%E4%BC%9F%E8%BE%BE%20VFlash%EF%BC%9AJim%20Fan%E5%AE%A3%E5%91%8A%E2%80%9CSystem-1%E8%A7%86%E8%A7%89%E6%96%B0%E6%97%B6%E4%BB%A3%E2%80%9D%EF%BD%9C%E6%A8%A1%E5%9E%8B%E6%8F%90%E9%80%9F12%E5%80%8D.md)/MEM 下沉 + WAM 动作块 + S0 阻抗/力控兜底）。
- ==数据分轨、数采生死线与千万小时 B300 账本==：跨过的只是「低质通用遥操堆时长」，S1 手部精细控力（SuperMimic 无手指、SONIC 仅三指）与部署 OOD 失败恢复仍强依赖真机交互数据；数采厂商生死线是「硬件品控/全流程良率 × 环境多样性」，LLM 自动标注（FLORA 1/125 成本 / [Perceptron \$29/h API](blogs/%E6%AF%8F%E5%B0%8F%E6%97%B629%E7%BE%8E%E5%85%83%EF%BC%8Cegocentric%20video%E8%BD%AC%E4%B8%BA%E6%9C%BA%E5%99%A8%E4%BA%BA%E8%AE%AD%E7%BB%83%E6%95%B0%E6%8D%AE.md)）不是替代者而是放大良率与多样性的杠杆。按 NVIDIA B300 集群做千万小时（4.3 亿 episodes、25–100 PB 压缩存储）第一性原理测算，成本结构与文本 LLM 完全倒挂：采集（\$50M–\$200M）+ 入湖（按 [Dyna](entities/companies/Dyna%20Robotics.md) 44 万 h/周需 5.2 月）+ Manifest CPU 内存（2.18 TB 击穿 GB300 单托盘 ~944 GB CPU RAM）+ 随机抽帧解码 I/O 放大 5–10× 远重于单 Epoch B300 FP8 GPU 算力（14B–30B WAM 仅需 702–1,505 卡 ≈ 10–21 柜 GB300 NVL72 / 30 天、\$2.3M–\$6.5M；含 3–5× 研发倍率约 28–70 柜、\$10M–\$30M；FLORA 标注仅 60 万 GPU-h ≈ \$1.5M–\$3M）。
- ==工业落地三象限与 Code-as-Policy/Memory==：结合桥介数物刘冲访谈（2026-11-18）与 [Lauren Tan](../AI%E5%BA%94%E7%94%A8%E4%B8%8E%E5%BC%80%E5%8F%91%E5%B7%A5%E5%85%B7/entities/people/Lauren%20Tan.md) `Code as Memory`（注：0.42% PR 返工率线索源自播客转述待一手直核），工业落地按「非标度 × 停线代价」裂解为三象限：① 低非标零容错 → AI 编写确定性工业代码+仿真验证（刘冲视角）；② 高非标低容错 → 成熟工业臂 + 抗极端近场传感 + 垂类物理世界模型（[Path Robotics](blogs/%E4%BC%B0%E5%80%BC%E8%B6%85170%E4%BA%BF%EF%BC%81%E5%85%84%E5%BC%9F%E4%BF%A9%E6%8A%8A%E2%80%9C%E4%B8%96%E7%95%8C%E6%A8%A1%E5%9E%8B%E2%80%9D%E5%A1%9E%E8%BF%9B%E7%84%8A%E6%9E%AA%EF%BC%8C%E5%B9%B4%E8%90%A5%E6%94%B6%E6%9A%B4%E6%B6%A817%E5%80%8D.md)）；③ 中高非标可重试 → 基模 + RaaS 按时/按件计费 + 远程人工/OOD 回流（[Tutor Intelligence](blogs/Investing%20in%20Tutor%20Intelligence.md)、[Dyna-2.1](blogs/Dyna-2.1_%20A%20Physical%20Agent%20for%20End-to-End%20Workflows.md)）。最优工业合体为「S2 用 Code-as-Policy/Memory 管流程护栏 × S1/S0 暴露高可靠神经网络物理原语」（[大晓机器人 57h 调代码仍 32% 残留](blogs/%E6%9C%BA%E5%99%A8%E4%BA%BA%E6%8E%A5%E7%AE%A1%E9%85%92%E5%BA%97%E6%B4%97%E8%A1%A3%EF%BC%81%E5%8F%8C%E8%84%91%E5%8D%8F%E5%90%8C%2BRSI%EF%BC%8C%E9%A1%B6%E7%BA%A7Astra%E9%A9%BE%E9%A9%B6%E5%91%98%E6%9D%A5%E4%BA%86.md)反证离散代码写不穿连续接触层）。
- ==数采商终局与商业护城河==：单一场景低良率中小数采厂必然加速出清（[Eidon AI 停摆开源复盘](blogs/Robotics%20Data%20is%20a%20Broken%20Business%20%26%20Robot%20Training%20Data%20Guide_%20Eidon%20AI%20Post-Mortem%20and%201%2C270%2B%20Hours%20Open%20Ego.md) + 2026 国内洗牌）；[光轮智能](entities/companies/%E5%85%89%E8%BD%AE%E6%99%BA%E8%83%BD%EF%BC%88Lightwheel%EF%BC%89.md)仿真仅占 ~20% 且同批真机 SysID 难对齐，借标准垄断下游数采渠道的逻辑不成立；第三方数采唯二高价值终局是「TSMC×NVIDIA 式绑定头部模型厂（如 [Maxinsights](entities/companies/Maxinsights.md) 绑定 Dyna/Genesis）」或「Scale AI 式跨客户短板情报套利（成为 Tier 2 巨头最快补短板的并购标的）」，但均受万台真机车队现场回流折旧与中立性悖论制约；应用层仍向结构化工位 RaaS、轻资产集成商（[AutoStore 立方体仓储深挖](https://mojojolite-sketch.github.io/%E5%85%B7%E8%BA%AB%E6%99%BA%E8%83%BD/autostore/refs/index.html)）与高复用 Adaptor 工具链（[Alex Zheng 旧金山报告](blogs/Where%20Physical%20AI%20Is%20Heading.md)、[Momenta 招股书镜像](blogs/%E5%A4%A7%E6%A8%A1%E5%9E%8B%E8%83%BD%E4%B8%8D%E8%83%BD%E5%90%83%E6%8E%89%E5%85%B7%E8%BA%AB%EF%BC%8C%E8%A6%81%E5%85%88%E7%9C%8B%E8%83%BD%E4%B8%8D%E8%83%BD%E5%90%83%E6%8E%89Momenta%E3%80%82.md)）收敛。

### 五问总览（2026-11-20；question-embodied-reusable-reliability@4）

1. 未解决的问题：如何同时做到“够聪明 + 够快”以通过换任务、换环境、换本体的真实节拍、良率、错误恢复与工位 ROI 验收？核心受制于云/边延迟墙（0.1–4 Hz vs 1,000 Hz）、手部精细控力缺失真机闭环、1–10 ms 刚性接触力控、千万小时入湖/Manifest 2.18 TB 内存墙，以及 20-DoF 多指灵巧手约 30 万次寿命硬伤。
2. 当前解决设想：S2 端侧并行规划（VFlash）+ 多尺度文本记忆（MEM / Dyna-2.1）+ Code-as-Policy/Memory 零幻觉流程编排；S1 端侧流匹配 WAM（GR00T 2 Turbo / Motubrain / $\pi_{0.7}$ RTC）+ 良率×多样性数据基建（Generalist UMI / Maxinsights MaxGlove / FLORA）；S0 冻结蒸馏运控小脑（SONIC / SuperMimic / NEXUS）+ 毫秒级视触力融合（ForceVLA2 / SynDexy C1）；商业按工业三象限与 RaaS 闭环推进。
3. 主导概念的实质与演变：从固定工位或单一网页语义 VLA，演化为 S2（认知规划与确定性代码编排）— S1（可调用物理原语、WAM 与数据编译金字塔）— S0（高频平衡与力控兜底）三层解耦；数据范式从混淆 S0/S1 遥操转向「S0 蒸馏复用 + S1 真机手部控力/部署 OOD 回流 + LLM 标注作良率杠杆」。
4. 被修正及新概念产生的原因：2026-11-18 桥介数物刘冲访谈点破全身小脑几乎不含手部控力（SuperMimic 无指、SONIC 仅三指）与 1,000 Hz PD/100 ms VLA 延迟墙；Goodfire 实证纯 VLA 停顿触发 +43%/-68% 误动作且缺失力学接地；大晓 57h 调代码仍 32% 残留证伪纯代码穿透连续接触；B300 千万小时测算揭示采集与 Manifest 内存先于 GPU 算力撞墙。
5. 必须逐项否定或限定边界的早期错误：演示≠部署；平均成功率≠产线可靠性；把 SONIC（S0）与 $\pi$（S1）混谈误判真机遥操门槛已全盘跨过；认为光轮凭仿真标准能垄断下游数采渠道；认为 LLM 自动标注将消灭第三方数采价值；认为纯云端 LLM 提速即可接管 1–10 ms 高刚度接触闭环；把工业落地二分为「黑盒 VLA vs 人工写死代码」。
