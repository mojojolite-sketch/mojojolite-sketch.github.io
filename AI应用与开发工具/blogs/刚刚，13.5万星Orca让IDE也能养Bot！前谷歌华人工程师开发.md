### 一、工程机制拆解：Bots Inside Your Agent IDE 与混合中继架构

1. Start anywhere. Finish in the IDE 的双端拓扑
   - 触发入口与本地执行解耦：传统异步编程 Bot（如云端沙盒 Agent）把代码克隆到远端容器，工程师难以介入中间态；Orca Bots 采用「云端轻中继 + 本机重执行」架构。据 [Orca Bots 安全与连接器文档](https://orca.dev/docs/bots/security)，每个 Bot 驻留在用户指定的一台本地电脑或已配对远程服务器文件夹中，通过本机主动向 Orca Cloud 建立出站长连接来拉取 Slack（`@bot-name` 频道提及或私信）、GitHub（Issue/PR 提及）、Linear（`@Orca <handle>` 或 `bot:<handle>` 标签）与 Webhook 事件，无需在开发机暴露公网端口（若机器休眠，Orca Cloud 暂存请求最长 24 小时，Webhook 请求体保留最多 7 天）。
   - BYO 订阅与零模型抽成：Bot 不自带模型计费，而是在用户本机直接调用已登录的 Claude Code、Codex、Cursor CLI、GitHub Copilot、Gemini CLI、Kimi Code、MiMo Code、Qwen Code、Hermes、Auggie、Kiro、Droid 或 Goose 订阅账号与 MCP/Skills 配置。当 Bot 在独立 Git worktree 中复现故障（例如官方演示的 Safari 结账首击失效问题：定位到 PayButton 监听 pointerdown 被粘性购物车遮罩吞掉，改用 click 修复并跑通 38 项 WebKit 测试与新建 PR）后，工程师可从 Slack 线程或手机端直接切回 Orca 桌面 IDE，在保留好的编辑器、终端与内置浏览器标签页内逐行接手。

2. 记忆可移植、24 套模板与高频状态恢复
   - 明文文件主权与迁移吸纳：据 [Bots 快速开始与导入文档](https://orca.dev/docs/bots/import)，每个 Bot 的角色设定（Soul）、记忆（Memory）与技能（Abilities）全部以本地目录内的纯文本/Markdown 文件保存，用户可直接编辑，也可在不改动原应用文件的前提下从 OpenClaw、Hermes 或其他 Bot 工具一键导入设定与定时规则；官方预置 24 套模板（覆盖 Bug 调查、PR 审查、CI 失败分析、发布说明、文档同步等），定时任务默认关闭以防止未配置仓库前误触发。
   - 针对长程并发会话的断点续航：2026-11-23 发布的 [v1.4.272](https://github.com/stablyai/orca/releases/tag/v1.4.272) 重点修补多 Bot 运行的三类典型断点——触发套餐用量上限并在切换账号或重启后自动续跑、应用崩溃或重启后恢复聊天与终端工作流（Resume work on restart）、以及支持 `/btw` 或 `/side` 旁路追问草稿，避免打断主任务节奏。

### 三、赛道横向对比：Orca vs. Conductor（Meta 并购关停）vs. 云端后台 Agent 沙盒

- 精准卡位 Conductor Cloud 关停窗口：本库此前追踪的 [Meta 收购 Conductor（Melty Labs）](Meta%E6%94%B6%E8%B4%ADConductor%EF%BC%9AAI%E7%BC%96%E7%A8%8B%E7%9A%84%E4%B8%8B%E4%B8%80%E5%9C%BA%E7%AB%9E%E4%BA%89%EF%BC%8C%E6%98%AF%E8%AE%A9%E5%A4%9A%E4%B8%AAAgent%E4%B8%80%E8%B5%B7%E5%B9%B2%E6%B4%BB.md) 已明确时间表——Conductor Cloud 于 2026-11-20 正式关停，桌面端仅维护至 2027 年初。恰在 11-20 当天，Orca 发布 v1.4.265 Bots 测试版并在官网上线 [Migrate from Conductor](https://orca.dev/docs/migrate-from-conductor) 指南（直接原地打开 Conductor 留下的 Git worktree 文件夹，零拷贝接管未提交变更与会话），意在承接从 Conductor 外溢的多 Agent 桌面用户。
- 中立调度壳 vs. 模型原厂垂直整合 vs. 云端 MicroVM：与 [Omarchy](Why%20AI%20Has%20DHH%20Working%2016-Hour%20Days.md) 采取「多 Harness 无偏好并存」类似，Orca 的壁垒在于跨模型订阅中立（同时容纳 Claude Code、Codex、Agy、Kimi、Qwen 等）以及「本地 IDE 状态连续性 + 移动端/IM 入口」；但这一中间层同样面临两头挤压——上游 Anthropic/OpenAI 正把后台调度与手机审批做进自家客户端（例如 Orca v1.4.280 不得不移除用 `agy` 查配额与写提交信息以对齐 Antigravity 集成规范），下游云端生产级并发则必须依赖 Firecracker/KVM MicroVM 沙盒而非本地 worktree。

### 观点与可反驳条件

- ==观点==：==Orca Bots 在 2026 年 11 月的爆发并非源于发明新的大模型或沙盒隔离原语，而是精准吃下了 Conductor Cloud 关停后的开源中立编排生态位，并用「本地 Git worktree + 出站云中继 + BYO 原厂订阅 + 移动端审批」把异步 Bot 与人类 IDE 接管缝合为单一工作流；但其长期商业壁垒取决于能否在纯开源免费外壳之上跑通企业级权限审计（Orca Enterprise）与跨机远程运行时（Remote Runtime），而非停留在个人极客的桌面多标签管理器==。
- ==推翻条件==：
  1. 若截至 2027-06-30，Anthropic（Claude Code）与 OpenAI（Codex）各自官方桌面/移动端均原生上线跨平台 IM 派活与本地多 worktree 接管，且 `stablyai/orca` 月均活跃贡献者（或发布周频）连续两季度下滑超 40% 且未形成公开的企业版付费客户案例，则「中立第三方 Agent IDE 具备独立商业留存护城河」的判断将被证伪。
  2. 若在 2027-09-30 之前，因本地 Git worktree 共享宿主机凭据边界与第三方 Connector/MCP 插件联动爆发大规模开发者密钥泄露或远端指令注入事故，迫使企业安全团队全面禁用本机常驻 Bot 而强制迁移至全云端 MicroVM 沙盒（如 Daytona / Modal / Cursor Cloud），则「本机执行 + 云中继」混合拓扑的主流化路径将被推翻。
