# 融资 1 亿美金，估值 12 亿美元，这家数据公司刚把自己的产品删掉重来

[本地原件归档](../../../raw/752d7f0acaf3c4d068e9f20bc46794807c2c19b675a7b2727d9db02568b75c8f) · 固定材料版本 `digest-material-752d7f0acaf3c4d068e9f20bc46794807c2c19b675a7b2727d9db02568b75c8f@1` · [一手原站](https://hex.tech/blog/hex-new-era/)

## 深度拆解与复核

- 口径与利益：触发线索为微信公众号「深思SenseAI」（2026-11-05）编译稿；本篇架构与融资拆解已穿透对照 Hex 联合创始人兼 CEO [Barry McCardel 官方博文《A new era for Hex, and data》（2026-10-27）](https://hex.tech/blog/hex-new-era/) 与产品主管 [Olivia Koshy 官方博文《Introducing Hex 4.0》（2026-10-27）](https://hex.tech/blog/introducing-hex-4-0/)，并结合其前置议程博文 [《The AI data sprawl》（2026-09-09）](https://hex.tech/blog/ai-data-sprawl/)、[《We got rid of our AI product team》（2025-05-12）](https://hex.tech/blog/we-got-rid-of-our-ai-product-team/) 及 [Hex 产品与 Threads 语义层概览](https://hex.tech/product) 交叉核查。Hex 在 D 轮节点高调宣布推倒重写带有明显的估值背书与对抗「SaaS 末日论」激励，且 StubHub 与 Ro 案例均属 Private Beta 内测自述、财务 ARR 与毛利全数未公开，下文先拆工程机制，再做账本与风险核查。

### 一、重写动因与 Hex 4.0 全代码架构机制（Semantic Layer、Threads、Notebook 与 DAG）

- 从“外挂 AI”到“先拆组织、再拆骨架”：Hex 于 2019 年由前 Palantir 成员 Barry McCardel、Caitlin Colgrove 与 Glen Takahashi 在旧金山创立，定位于整合 SQL、Python 笔记本、图表与交互式数据应用（2020–2021 年定型底层模型，服务 NBA、Cisco、Notion、Reddit、StubHub、Anthropic、Figma、HubSpot、Rivian 等逾 2,500 家客户）。早在 ChatGPT 发布前，Hex 即用 GPT-3 做过自然语言转 SQL 原型，并于 2023 年 2 月推出 Magic 功能；但到 2025 年 5 月，公司率先解散专门的 Magic AI 团队，将 AI 工程师打散并入按用户角色划分的主线产品团队（只保留底层 AI 平台组，AI 开发人力扩大 10 倍，提出「Magic 已死，现在一切都是 Magic」——类比 Mac 时代的 Sketch 需要单独设立云团队而 Figma 天生生长在云上）。
- 为什么创纪录季度后仍必须推倒重写（内部 3 道天花板 + 外部 AI Data Sprawl）：据 [Barry McCardel（2026-10-27）](https://hex.tech/blog/hex-new-era/) 披露，Hex 刚结束历史上最好的一个季度，却发现旧架构边际收益正在衰减：
  1. 内部 Agent Harness 极度臃肿：为了教会智能体点击基于 2020–2021 年假设搭建的专有 UI 与配置模型，运行层不得不塞入数百个专用工具（犹如给每位新同事强塞几百页操作手册）。
  2. 外部 Agent 只能走“钥匙孔”：Cursor、Claude、Codex 与 Cognition 只能通过有限的 MCP 接口窄口径调用 Hex，无法像读写原生代码仓库一样自由组合资产。
  3. 计算引擎并发能力错配：Agent 偏爱高速、高并发的反复试错迭代，而旧版执行引擎按人工逐格点击设计，响应延迟拖垮交互体验。
  4. 外部客户侧出现「AI 数据散乱（AI data sprawl）」：非技术人员绕开 Looker（Google 2019 年 \$26 亿收购）、Tableau（Salesforce 2019 年 \$157 亿收购）与 Microsoft Power BI，直接用 Cursor、Claude、Codex“凭感觉写代码（vibe coding）”生成一次性仪表盘与 HTML 文件并在 Slack 传阅，彻底失去权限隔离、来源追溯与指标观察性——本周一董事会汇报稿上的营收图表，无人知道由谁在哪天用哪张底表、漏掉了哪个过滤条件算出。
- ==Hex 4.0 的四层全代码协同机制==（据 [Olivia Koshy 官方发布（2026-10-27）](https://hex.tech/blog/introducing-hex-4-0/) 与 [Hex 产品文档](https://hex.tech/product)）：
  1. Plain Code 替代专有 YAML 与双界面协同（Notebook + Threads）：Hex 4.0 删掉了数百万行“AI 之前”的图形化构建器（如图表构建器与查询构建器），将每个项目的核心逻辑与可视化彻底改为纯文本标准代码文件（SQL/Python 等普通代码，而非专有 YAML 规格）。在交互层形成双面协同：技术人员使用重构后的 Notebook 作为“人与 Agent 的代码审阅协同面”（工作重心从手写转向审查与调整 Agent 产出）；非技术业务人员则通过面向自然语言问答的 Threads 界面提问——Threads 优先读取并约束在受治理的上下文（Context Studio）中。
  2. Semantic Layer（语义层）优先级锚定与可信度透视：在 Hex 4.0 中，Agent 并非生成散乱的孤立脚本，而是强制显式声明全部上游依赖并构建完整 DAG（有向无环图）。界面为非技术读者提供“元素级 Inspect 审查按钮”：点击任意 KPI 数字即可展开逻辑摘要、完整 SQL/Python 代码与底层表出处，并直观区分该指标是源自“经过数据团队认可的语义模型（Semantic Model，支持 Hex 原生建模及同步 dbt MetricFlow、Cube、Snowflake Semantic Views 等）”，还是需要数据团队复审的临时复杂拼凑逻辑（Alpha 内测客户 Ro 已在生产评估中使用该能力）。
  3. 开放 MCP 双向生态（Build Anywhere，Stop Fighting for the Entry Point）：Hex 不强迫用户只在自家对话框提问，而是借升级后的 Hex MCP Server 承接外部入口——用户可先在 Claude 生成一个数据 Artifact，再推送至 Hex 4.0 重建为受权控的可分享应用；或直接将现有 Hex 4.0 项目链接喂给 Cursor/Codex 进行任意位置编辑（Alpha 客户 StubHub 即用以纳管其全公司多来源 Agent）。应用发布后沉淀为团队可复用知识，供其他成员及其 Agent 持续追问最新数据。
  4. 重写的高并发流式计算引擎：引入三大计算改进——无依赖查询并行执行（Parallel logic execution）、单元完成后即刻流式出图（Results stream in as they're ready，不阻塞在未打开的标签页上）、以及基于 DAG 的增量缓存重算（调整筛选条件只重跑下游受影响节点，原本 Hex 3.0 需数分钟的交互在 4.0 实现悬停/点击实时响应）。

| 重写迁移与竞争防线风险 | 押注“一切皆代码”破除“SaaS 末日” | ❌ / ⚠️ 厂商乐观口径需降权复核：Hex 4.0 目前仍处于 Private Beta 内测阶段，官方承认“一等公民迁移工作流（first-class migration workflow）”仍在开发中；强行撤掉低代码图表/查询构建器对 2,500+ 存量客户的平滑迁徙构成实质履约压力。同时 Salesforce CEO Marc Benioff 在 Dreamforce 公开驳斥 SaaS 末日论、IDC 强调记录系统与审计框架壁垒，而底层数据仓库 Snowflake 与 Databricks 也正向自然语言分析（Threads 同类赛道）渗透。 |

- ⚠️ 本工作台核查（“语义层建设成本”被低估的反身性前提）：Hacker News 讨论中 OpenRouter 用户能够“1 人撑起全公司数据需求”的真实前提，是背后已经先行搭建了干净、无歧义的语义层（Semantic Layer）。生成 SQL 与图表的边际成本虽被大模型打到趋零，但定义“什么是活跃用户、口径何时切换”仍依赖数据工程师人工梳理——这也是 Hex 4.0（对齐本赛道 T3 规则代码化主线）必须用 DAG 血缘标识区分“语义模型认可指标”与“临时代码逻辑”的根本原因。
- ⚠️ 本工作台推断：Hex 选择在业绩峰值主动重写并拿了 \$100M 缓冲弹药，战略直指一个清晰判断——==当 AI Agent 让每个人都能生成 HTML 报表时，独立分析平台的护城河不在“生成按钮”，而在“承接 Claude/Cursor 外部产出的权限、血缘审计与语义口径控制点”==。但在“高算力推理成本压低软件毛利”的约束下，若其席位+用量混合定价未能跑通正毛利覆盖，或 2,500+ 老客户在迁移期内被 Snowflake/Databricks 原生分析工具截流，\$1.2B 估值将面临明显倍数消化压力。

### 三、BI 与数据工作台赛道横向对比

| 平台代表 | 核心定位与架构底座 | 外部 Agent 与 AI 接入方式 | 治理与血缘控制点 | 主要竞争脆弱性 |
| :--- | :--- | :--- | :--- | :--- |
| Hex 4.0 | 全代码项目（Python/SQL）+ Notebook / Threads + 并发流式引擎 | 原生开放 MCP Server，允许在 Claude / Cursor / Codex 创作后回流发布 | 强制全依赖 DAG + Inspect 按钮区分语义模型 vs 临时代码 | 仍在 Private Beta；混合用量计费毛利与 2,500+ 老客户迁移风险未解 |
| 传统 BI（Looker / Tableau / Power BI） | 专有数据模型 / LookML / 可视化报表中心 | 多以侧边栏聊天助手（Copilot Sidebar）形态外挂在既有 UI 上 | 强企业权限与既有记录系统，但难以纳管外部 vibe-coded 资产 | 外部 Agent 绕开传统 UI 导致架构老化；Looker 与 Tableau 在大模型期创新惯性大 |
| 云数据仓库（Snowflake / Databricks） | 底层存储计算底座向上延伸自然语言分析与 Notebook | 内置 Cortex / Genie / Semantic Views 与自有大模型推理 | 天然贴近底层物理表、审计日志与主权限体系 | 跨多源工作流协作与轻量化交互式应用（App）前端体验偏重、偏数据工程导向 |
| 独立数据工作台竞品（Deepnote / Sigma） | 云端协作 Notebook 或电子表格式云端 BI 探索 | 集成自然语言代码生成与表格公式辅助 | 依赖平台自身工作区权限与版本管理 | 缺乏 Hex 4.0 式激进全代码重构与 \$100M 级新弹药库，面临上游数仓与大模型双向挤压 |

### 观点与可反驳条件

- ==观点==：Hex 4.0 是企业级数据工具从“GUI 报表生产”转向“Agent 时代全代码血缘与语义治理层”的代表性范式重构——通过放弃专有配置与旧前端构建器、开放 MCP 承接 Claude/Cursor 外部生成流量并强制挂载 DAG 与语义模型审查徽章，Hex 正试图抢占企业防“AI 数据散乱”的控制枢纽（T3 样本）；但在不披露 ARR 与推理毛利的背景下，\$1.2B 估值实质是在预支混合用量计费跑通与存量客户无损迁移的双重成功。
- ==推翻条件==：
  1. ① 若截至 2027-Q3，Hex 4.0 正式 GA 并上线迁移工作流后 6 个月内，现有 2,500+ 企业客户向 4.0 全代码架构的迁移渗透率低于 30%，或因推倒旧版图表/查询构建器引发净收入留存率（NRR）跌破 110%，则“峰值期推倒重写能够无损换代”的战略判断将被证伪。
  2. ② 若截至 2027-12-31，Snowflake（Semantic Views + Cortex）与 Databricks（AI/BI Genie）在企业级市场以底层数仓捆绑形式拿下超过 40% 的日常自然语言分析预算，导致 Hex 在用量计费层面毛利率无法突破 65% 或被迫放弃独立商业软件溢价，则独立应用层“信任与血缘中枢”难以抵御底层数仓上攻的假设将被证伪。
  3. ③ 若 Hex 在 2027 年披露或行业交叉追踪显示其不得不依赖大幅压低席位费、且外部 MCP 调用回流仅占活跃任务不到 10%（用户仍停留在 Claude/Cursor 本地生成 HTML 分享而不入库 Hex），则“不抢入口、做可信接收端”的平台收敛逻辑将失效。
